# User Interface Internationalization (i18n) and Localization Rule

This document defines the mandatory architectural guidelines, workflows, verification checks, and constraints for managing user interface internationalization (i18n) and localized strings across the WhatsNexus codebase.

---

## 1. Single Source of Truth (`src/locales/`)

1. **Dedicated Directory:** All user-facing strings, system labels, hints, modal dialog messages, button texts, accessibility labels, and tooltips must reside strictly and exclusively in individual JSON dictionaries located at `src/locales/<lang-code>.json`.
2. **Canonical Reference:** `src/locales/en.json` serves as the primary ground truth and authoritative template for all localization keys across the entire application.
3. **No Alternative Stores:** Texts must never be imported, consumed, or parsed from arbitrary external APIs, secondary files, or inline dictionary literals inside renderer scripts. The IPC handler `load-locale` in `src/main.js` and `fetchLocaleJson()` in `src/renderer/renderer.js` strictly resolve to `src/locales/`.

---

## 2. Strict Zero-Hardcoding Policy

1. **HTML Templates (`index.html`, `src/assets/doom/index.html`, etc.):**
   - **No Plain Hardcoded Strings:** No user-visible text may be written directly inside HTML markup.
   - **Text Elements:** Must declare the `data-i18n="<key>"` attribute on the element (e.g. `<h3 data-i18n="welcome"></h3>`).
   - **Input Placeholders:** Must declare `data-i18n-placeholder="<key>"` or `data-i18n="<key>"`.
   - **Title Tooltips:** Must declare `data-i18n-title="<key>"` (e.g. `<button data-i18n-title="view_gpl_license_title">`).
   - **Accessibility Labels:** Must declare `data-i18n-aria="<key>"` (e.g. `<button data-i18n-aria="btn_close">`).
2. **JavaScript Scripts (`renderer.js`, etc.):**
   - Whenever dynamic text is created, rendered, or updated (via DOM APIs, dialogs, or desktop notifications), strings must be extracted from the active dictionary (`currentTranslations[key]` or `i18n[settings.language][key]`).
   - Hardcoded strings in error dialogs, auto-updater buttons, tray tooltips, and notification templates are strictly forbidden.
   - Any fallback argument supplied in code (e.g., `getTranslation(key, fallback)`) must strictly be written in neutral English.
3. **CSS Stylesheets (`style.css`, etc.):**
   - Pseudo-elements (`::before`, `::after`) must never inject visible language-dependent words via the CSS `content:` property. The `content` property is strictly reserved for empty layout spacers, glyphs, or decorative indicators (`content: ''`).

---

## 3. Mandatory 100% Key Parity Across All Locales

1. **Symmetric Dictionary Parity:** Whenever a new key is added, modified, or deprecated in `en.json`, it is mandatory that the exact same key suite is synchronized across **every single supported `.json` file** in `src/locales/`.
2. **No Missing Keys:** A build or release will be considered broken if any language dictionary lacks keys present in `en.json`. Every locale dictionary must have the exact same key count and identical key identifiers as `en.json`.

---

## 4. Strict Prohibition of English Placeholders (No "False Translations")

1. **Zero English Fallback Leakage:** Agents are **strictly prohibited** from copying untranslated English strings into foreign locale files as placeholders, lazy defaults, or stubs. Populating non-English files with English text violates our internationalization architecture.
2. **Mandatory Genuine Translations:** Whenever a key is added to `en.json`, the agent must provide authentic, contextual, grammatically correct translations for that key in **every active foreign locale** (`es.json`, `de.json`, `fr.json`, `hi.json`, `ar.json`, `ru.json`, `ja.json`, `zh.json`, etc.) in the exact same change cycle.
3. **Strict Whitelist for Identical Strings:** The *only* strings permitted to match `en.json` in foreign locale files are:
   - Official product and brand names: `"WhatsNexus"`, `"Freedoom"`, `"WhatsApp"`.
   - Game titles and protocols: `"Doomize"`.
   - Standard universal acronyms: `"GPLv3"`, `"GNU GPL v3"`, `"WebRTC"`, `"HTTP"`, `"SOCKS5"`.
   - Universal loanwords or geographic names where the target language naturally uses the identical spelling (e.g., `"Proxy"` or `"Argentina"` in languages where the native word is identical).
   Any common UI term (such as *"About"*, *"Interface language"*, *"Settings"*, *"Appearance"*, *"Notifications"*, *"Downloads"*, *"Close"*, *"Delete"*, *"Version"*) **must never** be left in English in a foreign locale file.

---

## 5. Constructed Languages (Conlangs) Architecture

WhatsNexus officially supports constructed languages (conlangs). Agents must strictly follow these glyphic and typographic rules:
1. **Klingon (`tlh.json` and `klingon.json`):**
   - Texts must not be left in Latin alphabet.
   - Strings must be encoded in the ConScript Unicode Registry (CSUR) Private Use Area block `U+F8D0`–`U+F8FF` (specifically letters `U+F8D0`–`U+F8E9`, digits `U+F8F0`–`U+F8F9`, comma `U+F8FD`, period `U+F8FE`).
   - This exact CSUR encoding is required for `Klingon-pIqaD.ttf` to render native pIqaD glyphs.
2. **Elvish Tengwar (`tengwar.json`):**
   - Texts must not be left in Latin alphabet.
   - Strings must be encoded using the ConScript Unicode Registry (CSUR) Private Use Area block `U+E000`–`U+E07D` required by `TengwarTelcontar.ttf` to render authentic Tengwar tengwar and témar glyphs.
3. **Esperanto (`eo.json`):**
   - Must use authentic Esperanto vocabulary with proper UTF-8 circumflex characters (`ĉ`, `ĝ`, `ĥ`, `ĵ`, `ŝ`, `ŭ`).
4. **CSS Attribute Selectors:**
   - Ensure `style.css` maintains `@font-face` bindings and `html[data-language="..."]` font-family overrides with `!important` for all conlang font stacks.

---

## 6. Language Registration & Dropdown Deduplication

When introducing or auditing a language:
1. **Single Registration Mandate:**
   - Register the language identifier code **strictly once** in the `supportedLanguages` array in `src/renderer/renderer.js`.
   - Register the native name **strictly once** in the `nativeNames` dictionary in `src/renderer/renderer.js`.
   - Multiple aliases (such as having both `'klingon'` and `'tlh'` simultaneously in `supportedLanguages`) are forbidden as they cause duplicate entries in UI select menus.
2. **Dynamic HTML Attributes:**
   - The renderer must reactively set `data-language` and `lang` on `document.documentElement` (`<html data-language="..." lang="...">`).
3. **Spellchecker Integration:**
   - Verify Chromium BCP-47 identifier mappings in `src/main.js` (`SPELLCHECK_MAP`) when applicable.

---

## 7. Mandatory Pre-Commit Validation Protocol

Before delivering any changes involving user interface markup, renderer scripts, or files in `src/locales/`, the agent **must execute an automated validation script** to verify:
1. **Parity Check:** Every `.json` in `src/locales/` contains 100% of the keys defined in `en.json` (0 missing keys).
2. **Fallback Leakage Check:** Check for untranslated strings across foreign locales. Any key identical to `en.json` that is not on the brand/proper noun whitelist must be flagged and corrected immediately.
3. **JSON Syntax Integrity:** Every file in `src/locales/` must successfully parse as valid JSON.
